## 结论与推荐

**这些资料中有能够实际运行的算法核心，但目前需要分层使用。** 优先采用数值已核对的 PLS、SVM 和 MC-UVE，CARS 修正输出与验证流程后作为变量筛选对照；手写 BPNN 可以迁移且适合向量化；CNN 可以迁移到 Python。若直接将所有压缩包解压、合并路径并运行主程序，当前云端环境下不能形成完整、可靠的中药研究流程。

本次按用户确认采用 **GNU Octave + Python** 实测。云端没有 MATLAB 可执行程序或已配置授权，**未进行 MATLAB 原生运行，也不将 Octave 结果表述为 MATLAB 验证通过**。不同 MATLAB 版本及其 Statistics and Machine Learning Toolbox、Deep Learning Toolbox 的兼容性仍须原生核验。

软件运行成功只证明所测输入和配置能够完成计算。中药样品 ID、产地核验、化学参考值以及独立批次评价仍决定科研可用性；本报告没有给出已验证的中药分类准确率或含量预测误差。

## 4. 关键数值核验

### 4.1 PLS 的 Octave/Python 一致性

使用 `0308 CARS+UVE.rar` 内 `corn_m5_starch.mat`：60 行校正数据、20 行测试数据、700 特征，4 个潜变量。Octave 执行上传的 PLS 核心，Python 使用 `PLSRegression(n_components=4, scale=False)`。

- 20 个测试预测的最大绝对差为 **1.7053×10⁻¹³**。
- Python 示例 RMSEP 为 **0.5168655**，数值单位沿用示例 y，未确认其物理单位。

这支持该 PLS 核心在本组输入上的数值可执行性。它不验证 `PLS.txt` 的另一套 PCA 后回归流程，也不等于中药成分定量已经成立。见 [数值检查](../reports/runtime/2026-10-30/numerical_checks.json)。

### 4.2 CARS 的误差输出确实被缩小

在 `CARS（sy）` 自带数据、同一随机种子与同一入选变量上，重新计算选定子集 CV：

| 项目 | 原输出 | 去掉缩放的工作副本 |
| --- | ---: | ---: |
| 独立重算的子集 CV 误差 | 0.0040694527 | 0.0040694527 |
| 函数报告字段 | 0.0014533760 | 0.0040694527 |
| 重算值/报告值 | **2.8** | **1.0** |
| 入选变量集合 | 14 个 | 相同 14 个 |

该补丁修复的是报告字段，不是降低预测误差。对应日志：[原字段核验](../reports/runtime/2026-10-30/logs/second-pass/verify_cars_error_scaling.log)、[修正核验](../reports/runtime/2026-10-30/logs/second-pass/patched_cars_error_scaling.log)。

### 4.3 IRIV 的超时具有可解释的边界原因

`generate_binary_matrix` 把每列一半位置设为 1，同时要求每行至少有两个 1。当仅剩 3 变量、20 行时，总共只有 30 个 1，而行约束至少要求 40 个，条件不可能同时满足；拒绝采样循环没有退出上限。剩 4 变量时条件虽可满足，但接受概率很低。

试验性保护在变量≤4时转入已有后向消除，并将 `Nx()` 写法整理成 `Nx`。相同 48×10 合成夹具约 1.46 秒结束、保留变量 `[1,4]`。这证明本次边界保护有效，尚不代表完整 IRIV 实现已获得广泛验证或构成新方法。

### 4.4 手工 BP 的向量化

保留 1500 行训练、500 行测试、24 输入、25 隐藏单元、4 输出、10 轮逐样本更新。新工作副本仅将重复的梯度双重循环改为矩阵计算，另保留必需的兼容 helper。

- 原循环单次耗时 **145.1019 秒**；向量化单次 **0.9787 秒**。
- 本环境这两次墙钟耗时相差约 **148 倍**，含加载/绘图等开销，不作为多机器、多次重复的稳定加速结论。
- 梯度的循环/矩阵对照最大差为 **8.88×10⁻¹⁶**。
- 两次输出的四类统计在显示精度内均为 `[0.8759, 1.0000, 0.6186, 0.9739]`。这是该语音教学示例的统计，不是中药结果；没有据此声称全部权重逐位相同。

### 4.5 PCA中心化与纹理条件的定向核验

保持同一训练min–max、PCA载荷和Kmeans质心，仅比较测试端是否减去训练均值：108条示例测试谱有 **73条最近质心归属改变**，投影平移的L2范数为 **11.69161**。这是内部数值和簇归属差异，不是产地准确率的差值；支持在使用原主程序前修正测试投影。

纹理文档的原始Word XML中确实存有 `if j P(...)` 等缺少灰度邻接比较的片段。将固定循环尺寸缩到16并直接输入uint8 RGB数组（避免PNG被自动保存为索引图像），保持共生矩阵条件不变：纯色与随机图像得到相同8维输出，最大差为0，约3.03秒完成。缩小尺寸及输入矩阵适配均已记录；它复现的是所存代码的条件缺失，不是对标准GLCM算法的否定。灰度/索引输入还会触发 `Gray` 未定义。

## 5. 示例数据本身的科研限制

### 5.1 CNN 示例存在训练/测试完全相同的特征行

`0627` 包的 `data.mat` 有 252×1007 训练矩阵、108×1007 测试矩阵。本次按完整浮点特征向量逐字节比对，发现 **9 条测试谱与训练谱完全相同（9/108，约 8.33%）**，对应标签一致。匹配的下标见 [重叠记录](../reports/runtime/2026-10-30/example_overlap.json)。

这直接影响“未知样本”评价的可信度。并不是说其余测试谱均无问题，也不是说全部高分都由这 9 条重复造成；资料还缺物理样品和批次映射。本次保留原示例用于软件运行检查，没有把其准确率作为可发表泛化证据。

Python SVC、Octave LIBSVM、PyTorch CNN 在这份示例上出现的高分均按这个口径处理。迁移后的 CNN 使用 MATLAB 列优先的 32×32 重排布局，143148 个参数，CPU 训练 3 轮；最终布局核验后的示例准确率为 **96.30%**，训练过程约 **2.14 秒**。它是结构迁移与前后向计算检查，**不是 MATLAB 原网络权重或原 100 轮训练的严格复现**。早期采用行优先重排的尝试保留在日志并标为已替代，以列优先重跑结果为准。

## 6. 已做的适配与仍需修复的逻辑

**兼容适配**包括 `sumsqr`、有限的 `mapminmax` train/apply 接口、均匀随机初始化 `rands`、Kfold 划分 helper、脚本局部函数拆分、Octave LIBSVM 三输出调用、绘图属性/API 调整。它们写在独立工作副本中，不能据此宣称 MATLAB 所有同名 API 已被完整实现。

**逻辑/研究协议问题**仍包括：CARS 误差缩放、MC-UVE 有符号排序的截取策略、IRIV 边界、PLS 合并训练/测试归一化、PCA 测试中心化遗漏、SSA 复用调参折报告分数、部分 CNN 验证/测试用途混用、扫描/样品/批次混淆。算法能结束与这些问题是否修复是两项记录。

测试过程中也保留了执行器适配自身的失败尝试：一版 SSA 绘图属性替换正则误处理了含分号的标签表达式，已修正后重跑；合成 XLSX 与 Octave io 读入相遇到关系表错误，之后改为 MAT 矩阵注入。它们在 `cases.json` 标注为适配/夹具问题，没有归责于原算法。

PCA定向夹具的首次调用误取了Kmeans第一个输出（归属）作为质心，也已修正重跑；纹理小PNG夹具的颜色编码问题则通过直接RGB输入隔离。所有尝试保留，最终结论使用已核对的场景。

纹理函数的45秒日志含大量逐循环短路操作兼容警告，原始日志约112.9MB。因此该超时还包含显著的日志输出开销，不能直接当作算法纯计算耗时。超1MiB日志提供可浏览首尾摘录及完整 `.log.gz`，同时记录解压后的字节数和SHA-256；没有丢弃完整输出。

## 7. 建议采用的软件路线

1. **主研究实现使用 Python**：以已核对的 PLS、SVC/SVR、明确的分组嵌套验证为基础，统一坐标/参考列/样品元数据接口。当前基础测试 7 项通过，但仍需真实标签才能进入中药模型验证。
2. **保留 Octave 作为传统算法核验工具**：PLS、CARS、MC-UVE、Random Frog 可在固定版本、独立路径中复核；不要合并所有工具箱的同名函数。
3. **CARS/MC-UVE 迁移后再做稳定频段改进**：每个训练分区内重新筛选，以独立样品/批次为重采样单元，比较变量数、稳定性和外部性能。
4. **SSA 作为同预算优化器对照**：先修复内外层验证；完整默认迭代计算成本需要纳入方案，不能只比较最优准确率。
5. **CNN 保持独立迁移模块**：先修数据划分、对比1D结构及简单基线；现有2D重排并不为中药提供天然空间信息。
6. **成分定量和小样本校准**：补真实化学值、独立样品及跨批次数据后执行。当前没有交付一个已验证的中药成分模型或校准模型。

GaussView Windows 安装包未运行，它不是本轮光谱模型训练依赖。软件角色与原有来源说明见 [算法审读](ALGORITHM_REVIEW.md)。
