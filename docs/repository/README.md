## 后续更新方式

1. 先获取远程分支，再刷新Git清单：

   ```bash
   git fetch --prune origin '+refs/heads/*:refs/remotes/origin/*'
   python scripts/refresh_repository_inventory.py
   python scripts/refresh_repository_inventory.py --check
   ```

2. 读取每条计算线的新 `status/progress/summary`，同时保存固定SHA、路径、来源文件SHA-256和实际心跳时间。将新观测补入轮次台账与本页状态；Git刷新脚本只更新Git字段，保留人工训练状态。
3. 新增训练须给唯一轮次ID，并记录数据/协议/父轮次/任务单位。备份、续算、复核标明原轮次；有输入变化才说明为何另立实验，不以新对话或新分支自动编号。
4. 同时对照 `progress` 与验收 `summary`：队列结束、尝试全部目标、达到阈值和全论文合格是不同状态。较新心跳优先用于运行判断，分子合格仍按对应数值模型的验收证据判断。
