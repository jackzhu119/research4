# E05 新批次验证准备协议（2026-11-10）

**状态：NOT_RUN_NEEDS_NEW_BATCH_DATA。** 当前只有元数据模板、导入验证器和预先设计的采样方案，没有新增批次样品，没有训练或评价新批次模型。既有来源组每组单批的声明不能提供来源与真实批次的独立变化；缺失的真实批次编号继续缺失。

## 采样目标与数量依据

优先采集纯酸枣仁 ZY03—ZY07 所对应的五个已知来源组的新独立批次，保持来源名称的原始粒度；“山西”与“山西灵石”不解释为互斥行政区域。每个来源每个新批次计划 **10 份 Support＋20 份独立 Query＝30 份实物样品**。每类 K=1/3/5/10 从固定 10 份支持池嵌套抽取，Query 始终冻结。五来源的一轮新批次合计 150 份，其中 50 份支持、100 份查询。这是可执行的标签预算，并非已经完成的统计功效分析；20 个查询仅有 5 个百分点的单类准确率分辨率，不足以确认小幅改善。

如采集条件允许，优先每来源至少 **3 个独立新批次**，覆盖独立采收或采购批次并保留原始证据，而不是把一个批次拆成多个虚构编号。五来源共 450 份实物，其中 150 份支持、300 份查询。三个批次仍不足以稳定估计批次总体效应；优先增加独立批次数，其次增加同批 Query。具体功效和更大样本数应根据本轮各来源误差率、预先指定的最小实际效应及配对相关性做新协议估计，不能看新批次 Query 后补选效应量。

二分类来源域机制的外部检查可另行采集枣仁 ZY01 对应来源的新独立批次，并匹配同批次定义和每批 10 Support＋20 Query 的角色预算。与上述五酸枣仁来源各三个批次配套时，再增加 90 份枣仁实物，总预算为 540 份。两任务应分开统计；五分类和二分类总标签量不同，不能用准确率相减解释类别数因果效应。ZY02 极小组不能替代有足够独立样品的来源对照。

## 入库元数据与实际证据

填写同目录的 `new_batch_metadata_template.csv`；只填真实记录，不生成、推断或从文件名补造 `true_batch_id`。必需核查：物理样品 ID、用户确认种类、来源组、真实批次标识、采集日期、仪器标识、测量日期、制样流程、谱文件、标签核验依据与 Support/Query 角色。`thickness` 和 `moisture` 缺失保持空白并记录局限；已测值须附制样记录中明确的单位与方法，不能混用单位。用户确认种类与来源不等于独立植物学鉴定；尽可能提供凭证标本、采样日志或独立鉴定依据。

CSV 谱文件使用两列：坐标轴和信号值，可带一行标题。工作簿中的某一谱列须显式定位，例如 `spectra.xlsx#sheet=吸收系数&column=实际样品列名`，轴为工作表第一列。路径相对于元数据文件所在目录；不扫描目录发现数据。一个工作簿可保存多个样品，不可将同一谱列登记为不同实物。验证器检查引用存在、数值有限、坐标严格递增；同轴、轴单位、仪器参考、吸收系数反演及厚度/含水率条件须按原始记录另行审计，不能仅靠文件数值通过即宣布科学质量合格。

## 冻结、拟合与评价顺序

1. 核实新批次与旧数据的实物 ID 无交叉，保存原始文件、元数据、来源证据 SHA-256。检查同一实物的重复测量，按实物分组，不能让重复谱跨 Support/Query。
2. 在读取 Query 标签做评价前，冻结旧批次训练模型及全部预处理、特征、参数、分类规则和输入哈希；仅在旧批次训练侧拟合。旧模型不得因新 Query 表现重新选参。
3. 按真实批次与来源分层，以预先固定随机规则冻结 10 份/类支持池和 20 份/类独立查询池；先公布逐样品 ID 和角色。所有比较使用相同支持、查询及嵌套 K。Support 标签仅用于预先指定的 Identity、Bias-only、Anchor λ=1、保守校准；如增加完整重训，单独列为新增标签重训方法。
4. 只在所有冻结、质量、标签和批次审计通过后执行最终 Query 评价。禁止根据 Query 更换支持实物、删错分样品或选择 K。保存逐实物真值、预测、原始及校准分数、模型/输入哈希和计算成本。
5. 分开报告每来源、每真实批次、每类 Recall、Accuracy、Macro-F1、Balanced Accuracy、纠错与误伤；描述性区间保留样品相关性，并在批次足够时考虑批次层级。批次很少时报告不确定性而不宣称稳健跨批次总体因果效应。
