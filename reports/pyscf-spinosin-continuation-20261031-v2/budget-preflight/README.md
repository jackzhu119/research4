# 独立续算预算执行器核验

新执行器：`scripts/run_pyscf_continuation_budget_20261031.py`。17项测试通过，实际最终测试子进程CPU2.51994秒；这些是小型进程／合成元数据夹具，新增SCF、梯度、优化或Hessian任务为0。

该执行器只接受新schema `research4-pyscf-continuation-budget-v2`；初始化绑定用户追加授权的文件SHA、上轮aef64c6源版本及上轮检查点SHA。之后每阶段再次核验，旧pilot预算路径和旧schema不能重用，已有账本不能重置。此预检没有初始化科研账本或启动科研worker。

默认新批次总上限43200 CPU秒／28800墙钟秒；每阶段最多21600 CPU秒／14400墙钟秒，线程1—4、地址空间最多12 GiB。总墙钟从初始化起计，包含阶段间等待。每阶段请求会按原剩余额度向下裁剪，绝不自动扩大。父进程使用wait4的user＋system实际CPU累计；线程数不用于乘算估计CPU。

生产阶段至少65 CPU秒及61墙钟秒，以便保留至少60 CPU秒的SIGXCPU软／硬限间隔，以及60墙钟秒的SIGTERM清理窗；阶段墙钟参数已经包含清理窗，到上限会SIGKILL兜底。总CPU另留随线程数变化的边界余量，总墙钟另留2秒边界余量。监督器收到SIGINT／SIGTERM也会转发停止请求并等待有界清理。

测试实际读取了子进程的线程环境和RLIMIT_CPU，验证四个线程变量一致。busy夹具为节省资源，在继承生产限额后主动将自己的CPU限额降低到1／2秒，再验证真实CPU终止与wait4失败记账；不是把生产60秒裕量改成1秒。sleep夹具在61秒阶段的第1秒收到TERM并退出，剩余60秒清理窗可用但无需等满。

拒绝检查覆盖未授权、错授权／检查点哈希、错源版本、总／分阶段超限、未结束或重名阶段、旧日志、篡改CPU总数及总墙钟deadline。启动失败记录actual_cpu_seconds=0，进程自然退出与信号请求竞态不会留下假RUNNING状态。所有数据失败条件保留原文件，不修改历史科研结果。
