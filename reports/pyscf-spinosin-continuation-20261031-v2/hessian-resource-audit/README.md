# 斯皮诺素Hessian磁盘与方法一致性审查

## 为什么释放SCF缓存仍不能直接算默认DF Hessian

Spinosin维数由上轮真实结果确认：75原子、762个轨道AO、2459个辅助AO、闭壳层占据轨道160。当前方法PBE无HF交换，因此DF Hessian调用`with_k=False`，辅助基响应仍为2。

实际源码`pyscf/df/hessian/rhf.py`中存在下面的临时HDF5数值数据：

| 阶段／数据 | float64尺寸 | 是否在纯PBE路径写入 |
|---|---:|---|
| partial Hessian `rho_ip1` | 34,267,286,304字节，约31.91 GiB | 是；全75原子时逐AO行完整写入 |
| partial Hessian `wk_ip2` | 声明同样约31.91 GiB | `with_k=False`时未写入，不计为实际占用下界 |
| H1生成 `rho0_Pij` | 约10.64 GiB | 是；全部AO行的分组数值数据 |
| H1生成 `wj_ip1_pij` | 约31.91 GiB | 是；辅助基响应非零时全部写入 |
| H1生成 `vj1_buf` | 约0.97 GiB | 是；数值缓冲也写入同一个HDF5临时文件 |

后面三个数据同时存在于H1生成器的临时文件，数值负载下界为**46,734,874,272字节（43.525 GiB）**，还不包含HDF5元数据。审查时`/tmp`实际剩余9,441,312,768字节。前一阶段与后一阶段的临时文件不应相加作所谓峰值，但任一阶段下界都已超出当前磁盘。

这与SCF的5.326 GiB积分缓存是不同的结构。释放SCF缓存有助于梯度内存／分块，不会消除Hessian代码写出的上述全局临时数据。`max_memory`只影响部分分块，不改变这些全局数据维数；`atmlst`删减原子不是完整219振动模式计算，且H1生成仍构建全部AO行数据。设置辅助基响应0会改变导数近似，不能作为等价捷径。在本次审阅的内置实现中没有找到无需这些全局存储的配置开关；未擅自重写Hessian公式或修改库。

RAM部分仅列出明确数组尺寸，并不是实测峰值：H1 AO数组约0.97 GiB；可能重建的CPHF阶段SCF DF缓存约5.326 GiB；名义480辅助函数的三分量导数积分块约6.23 GiB；还有其余临时数组与运行时空间。这些数组不一定同时存在，不能直接相加冒称峰值。`wk_ip2_P__`在辅助基响应2时的1.407 GiB空数组即使无交换也会声明，但虚拟地址分配与真实RSS也不能混淆。

## 非DF RKS解析Hessian的可行替代，尚未运行

`pyscf/hessian/rks.py`调用普通`pyscf/hessian/rhf.py`；其`_get_jk`通过`pyscf.scf._vhf.direct_bindm`对屏蔽后的四中心导数积分立即收缩，没有上述强制DF全局HDF5张量。因此有工具层面的低磁盘替代方向，但这不是对运行时间、峰值内存或最终成功的保证。

去掉DF仍可使用PBE／def2-SVP／同网格／无D3，但DF近似已经变化，不能把DF优化结果直接标成同方法的非DF频率。必须另立方法标识并实际执行：

1. 非DF小分子完整Opt/Freq软件验证。
2. 目标几何上的新非DF SCF及核梯度，明确电荷、自旋、基组、泛函及网格。
3. 如未满足相同几何收敛条件，执行非DF几何优化；不能放宽阈值。
4. 在独立CPU、内存、磁盘约束下执行非DF Hessian／CPHF及219完整模式检查。
5. 保留原始Hessian，只有小幅非对称通过阈值时才按明确规则对称化；零／负频率均不能称为通过的极小值。IR仍为NOT_COMPUTED。

普通RHF实现对小体系可能自动缓存四中心ERI；后续非DFworker应明确使用直接收缩路径，`mol.incore_anyway=False`、`_eri=None`，必要时把`get_jk`明确转交`hf.SCF.get_jk`以绕过RHF的内存启发式。完整762⁴双精度张量只是约2.7 TB的算术示例，**不是直接积分方法的实际内存需求**，也不是宣称它真的申请了该数组。

非DF对DF频率／能量可能存在真实拟合差异，不应通过选峰或改频率使两种近似强行相等。两种流程都仍是孤立分子模型，不能仅凭频率相近确认药材中的化学成分或来源。
