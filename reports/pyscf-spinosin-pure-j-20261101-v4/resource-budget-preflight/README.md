The previous actual 111023.488913 CPU seconds remain historical cost, separate and immutable. Real completed-phase charge is final wait4 user+system. `/proc` monitoring uses the complete process history since birth; native threads are not summed twice, and an unexpected second payload process is rejected. Prior-V3/current-V4 locks prevent overlapping use by those runners; there is no claim of a universal lock on every older runner.

CPU and RSS guards are best effort. The 0.1-second sampling interval and 120 CPU-second reserve leave substantial headroom for four threads, but OS scheduling, process status reads and signals have latency. Group identity is rechecked before each signal with a documented non-atomic group-signal boundary. Unreaped original-child containment has a narrow direct-PID fallback if pidfd is unavailable. Profiling RLIMIT_CPU is an additional, unproven exact-CPU bound: previous phase overruns remain recorded rather than hidden. The guard cannot add RAM, provide paid storage, restore missing Hessian data, or prove scientific convergence.
